# PROMPT MAESTRO — SISTEMA DE GESTIÓN DE DEPÓSITO
## Stack y restricciones técnicas OBLIGATORIAS

Construye una aplicación web completa con:
- Backend: PHP 8.2 + Laravel 11
- Base de datos: MySQL 8
- Frontend: CSS puro + JavaScript vanilla (sin compiladores, sin npm run dev)
- Estilos: Tailwind CSS vía CDN: <script src="https://cdn.tailwindcss.com"></script>
- Alertas: SweetAlert2 vía CDN: <script src="https://cdn.jsdelivr.net/npm/sweetalert2@11"></script>
- NO usar: Vite, Vue, React, Node, npm run dev, webpack, ni ningún bundler
- Notificaciones push: Implementar con Laravel Broadcasting + Pusher (o Laravel Reverb) + JS nativo
- Arquitectura: MVC estricto con Laravel, API RESTful interna + vistas Blade
- Diseño: Moderno, oscuro (dark theme), industrial/minimalista, con sidebar fijo y topbar

---

## DISEÑO VISUAL OBLIGATORIO

El sistema debe tener una estética industrial-tech, dark theme principal:
- Fondo general: #0f1117 (casi negro)

Cada página debe tener:
1. Sidebar fijo izquierdo (colapsable en mobile)
2. Topbar con: nombre del sistema, campana de notificaciones (con badge contador), breadcrumb

## BASE DE DATOS — MIGRACIONES COMPLETAS

### Tabla: products
- id (bigIncrements)
- product_code (string, unique, not null) -- código obligatorio y único
- name (string, nullable)                 -- nombre opcional
- photo (string, nullable)                -- ruta de imagen
- available_quantity (integer, default 0) -- cantidad disponible (no dañados)
- damaged_quantity (integer, default 0)   -- cantidad marcada como dañada/mala
- minimum_stock (integer, default 5)      -- umbral de alerta
- is_active (boolean, default true)
- deleted_at (softDeletes)
- created_at, updated_at

### Tabla: product_entries (tickets de entrada)
- id (bigIncrements)
- entry_code (string, unique)  -- código autogenerado tipo ENT-2024-001
- entry_date (date)
- entry_time (time)
- notes (text, nullable)
- created_by (string, nullable)
- created_at, updated_at

### Tabla: product_entry_items (ítems de cada ticket de entrada)
- id
- product_entry_id (FK -> product_entries)
- product_id (FK -> products)
- quantity_received (integer)
- quantity_damaged (integer, default 0)  -- cuántos llegaron dañados
- damage_notes (text, nullable)          -- descripción del daño al recibir
- created_at, updated_at

### Tabla: product_exits (tickets de salida)
- id (bigIncrements)
- exit_code (string, unique)   -- código autogenerado tipo SAL-2024-001
- exit_date (date)
- exit_time (time)
- technician_name (string, nullable)    -- nombre del técnico
- license_plate (string, nullable)      -- patente del vehículo
- is_for_workshop (boolean, default false) -- checkbox "es para uso del taller"
- notes (text, nullable)
- created_by (string, nullable)
- created_at, updated_at

### Tabla: product_exit_items (ítems de cada ticket de salida)
- id
- product_exit_id (FK -> product_exits)
- product_id (FK -> products)
- quantity (integer)
- created_at, updated_at

### Tabla: product_histories (log global de todo movimiento)
- id
- product_id (FK -> products)
- action_type (enum: 'created','updated','entry','exit','damaged_marked','photo_updated')
- reference_type (string, nullable)  -- 'ProductEntry', 'ProductExit', etc.
- reference_id (integer, nullable)   -- ID del registro relacionado
- description (text)                 -- descripción legible del evento
- technician_name (string, nullable)
- license_plate (string, nullable)
- quantity_change (integer, nullable)
- quantity_before (integer, nullable)
- quantity_after (integer, nullable)
- created_at

### Tabla: stock_alerts
- id
- product_id (FK)
- alert_type (enum: 'low_stock','out_of_stock')
- current_quantity (integer)
- minimum_stock (integer)
- is_read (boolean, default false)
- created_at, updated_at

## MODELOS Y RELACIONES

### Product.php
Relaciones:
- hasMany(ProductEntryItem::class)
- hasMany(ProductExitItem::class)
- hasMany(ProductHistory::class)
- hasMany(StockAlert::class)

Accessors:
- getTotalQuantityAttribute()  // available_quantity + damaged_quantity
- getStockStatusAttribute()    // 'ok' | 'low' | 'critical' | 'out'

Scopes:
- scopeLowStock($query)        // where available_quantity <= minimum_stock
- scopeWithDamaged($query)     // where damaged_quantity > 0

Usar SoftDeletes para no perder historial.

### ProductEntry.php
- hasMany(ProductEntryItem::class)
- hasManyThrough(Product::class, ProductEntryItem::class)
- Boot: auto-generar entry_code con formato ENT-YYYY-NNNN

### ProductExit.php
- hasMany(ProductExitItem::class)
- Boot: auto-generar exit_code con formato SAL-YYYY-NNNN

### Rutas:
GET    /products                          -> index
GET    /products/create                   -> create form
POST   /products                          -> store
GET    /products/{id}                     -> show (ficha)
GET    /products/{id}/edit                -> edit form
PUT    /products/{id}                     -> update
DELETE /products/{id}                     -> destroy (soft delete)
POST   /products/{id}/photo               -> update photo only

### Lógica de negocio en ProductController:
- Al hacer store/update: registrar en product_histories
- Al actualizar damaged_quantity: registrar evento 'damaged_marked', recalcular available_quantity
- Al guardar: verificar si available_quantity <= minimum_stock -> crear StockAlert + disparar LowStockEvent
- Foto: guardar en storage/app/public/products/, generar URL pública

## MÓDULO 6 — NOTIFICACIONES PUSH

### Sistema de notificaciones en tiempo real:

Usar Laravel Broadcasting con Laravel Reverb (open source, self-hosted) o Pusher.

Configuración:
- Instalar via composer los paquetes necesarios
- Configurar BROADCAST_DRIVER en .env
- Crear canal deposito-notifications

Eventos a broadcastear:
1. LowStockEvent: cuando un producto llega al stock mínimo
2. ProductMovementEvent: cuando hay una entrada o salida registrada

Ambos eventos deben implementar ShouldQueue para procesarse en cola.

Frontend (notifications.js — JS vanilla puro):
- Conectar al canal y escuchar eventos
- Mostrar notificación toast personalizada SIN librerías externas
- Incrementar badge contador en campana del topbar
- Guardar notificaciones no leídas en localStorage
- Al hacer click en campana: mostrar panel dropdown con historial de notificaciones

Toast de notificación (CSS + JS puro):
- Aparece desde esquina inferior derecha con animación slide-in
- Tiene: icono de color según tipo, título, descripción, barra de progreso animada, botón X
- Auto-desaparece en 5 segundos
- Se pueden apilar múltiples toasts
- Transición de entrada/salida con CSS transforms y opacity

## MÓDULO 7 — VALIDACIONES Y SEGURIDAD

### StoreProductRequest:
- product_code: required|unique:products,product_code|max:50
- name: nullable|string|max:255
- photo: nullable|image|mimes:jpg,jpeg,png,webp|max:2048
- available_quantity: required|integer|min:0
- damaged_quantity: nullable|integer|min:0
- minimum_stock: required|integer|min:0

### UpdateProductRequest:
- product_code: required|unique:products,product_code,{id}|max:50
- (resto igual que store)

### StoreEntryRequest:
- entry_date: required|date
- entry_time: required
- items: required|array|min:1
- items.*.product_id: required|exists:products,id
- items.*.quantity_received: required|integer|min:1
- items.*.quantity_damaged: nullable|integer|min:0
- items.*.damage_notes: required_if:items.*.quantity_damaged,>0|nullable|string

### StoreExitRequest:
- exit_date: required|date
- exit_time: required
- technician_name: required_if:is_for_workshop,false|nullable|string
- license_plate: nullable|string|max:20
- is_for_workshop: required|boolean
- items: required|array|min:1
- items.*.product_id: required|exists:products,id
- items.*.quantity: required|integer|min:1
- Validación custom: quantity <= available_quantity del producto (usar withValidator)

### Middleware adicional:
- EnsureProductHasSufficientStock: validar stock antes de registrar salida
- Manejo global de errores con respuestas JSON consistentes para rutas /api/*

## CONSIDERACIONES DE ESCALABILIDAD — OBLIGATORIAS

Implementar desde el inicio sin excepción:

1. ÍNDICES EN DB: agregar índices en:
   - products: product_code, deleted_at
   - product_exits: technician_name, license_plate, exit_date
   - product_entries: entry_date
   - product_histories: product_id, action_type, created_at, technician_name, license_plate
   - stock_alerts: product_id, is_read

2. PAGINACIÓN: TODAS las listas usan paginate(25). Nunca usar get() o all() en listados.

3. EAGER LOADING: usar with() en todas las queries que accedan a relaciones.
   Ejemplos:
   - ProductEntry::with(['items.product'])->paginate(25)
   - ProductExit::with(['items.product'])->paginate(25)
   - Product::with(['stockAlerts'])->paginate(25)

4. TRANSACCIONES DB: envolver en DB::transaction() toda operación que modifique múltiples tablas.
   Obligatorio en: store de entries, store de exits, update de damaged_quantity.

5. QUEUE: los eventos LowStockEvent y ProductMovementEvent implementan ShouldQueue.
   Configurar QUEUE_CONNECTION=database en .env y crear tabla de jobs.

6. CACHÉ: el DashboardController usa Cache::remember() para métricas con TTL 60 segundos.
   Invalidar caché al registrar nuevas entradas o salidas.

7. ELOQUENT SCOPES: usar scopes para filtros reutilizables en lugar de repetir queries.

8. SOFT DELETES: implementar en Product model con SoftDeletes trait.

9. API RESOURCES: usar Laravel API Resources para todas las respuestas JSON.
   Nunca retornar modelos Eloquent directamente en las respuestas API.

10. SELECT ESPECÍFICO: en queries de listado usar select() para traer solo columnas necesarias.
    Evitar SELECT * en tablas con muchas columnas o con columnas de texto/blob grandes.

## README.md — CONTENIDO REQUERIDO

Generar README.md con:

### Requisitos del sistema
- PHP 8.2+
- MySQL 8+
- Composer 2+
- Extensiones PHP: pdo_mysql, gd, fileinfo, mbstring

### Instalación paso a paso
1. git clone o descomprimir el proyecto
2. composer install
3. cp .env.example .env
4. php artisan key:generate
5. Configurar DB_HOST, DB_DATABASE, DB_USERNAME, DB_PASSWORD en .env
6. Configurar BROADCAST_DRIVER y credenciales de Reverb/Pusher en .env
7. php artisan migrate --seed
8. php artisan storage:link
9. php artisan queue:work (en terminal separada, para notificaciones)
10. php artisan reverb:start (si se usa Reverb, en terminal separada)
11. php artisan serve
12. Abrir http://localhost:8000

### Correr tests PHP
php artisan test
php artisan test --coverage

### Importar colección Postman
1. Abrir Postman
2. Import -> File -> seleccionar postman_collection.json
3. Configurar environment con base_url=http://localhost:8000
4. Para tests que requieren CSRF: primero hacer GET / y capturar el token
